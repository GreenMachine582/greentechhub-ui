gth-toast (failed requests)

toast.js toasts any failed htmx request on its own: 4xx/5xx (a FastAPI JSON detail becomes the message), network failures and timeouts. It stays quiet for 422 (inline form errors), when the response sends its own toast, and inside data-gth-error-toast="off".

For a network failure, switch DevTools to offline and press any button.

gth-alert (inline)

The same card as page content: it fills its container, sits in the flow and stays until the page changes, with no close button. Use it for a form or result error, or a "not set up yet" notice; use a toast for something that just happened.

gth-alert-banner

Site-wide strips for maintenance or degraded service. app.html renders the optional site_banners list above the navbar: this page's banner at the top comes from it (the playground only adds it here, so other pages keep their layout). Dismiss it and reload: it stays hidden, from before first paint, because its id is remembered with its message. Change the message and it shows again. Without an id a banner only closes for this page view.
