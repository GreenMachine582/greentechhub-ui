# 🎨 Theming & Static Assets

## Theming

- CSS custom properties (`--gth-color-primary`, `--gth-space-*`, `--gth-font-*`), defined in `theme/tokens.py` and layered on top of the vendored CSS framework's variables — override, don't fork it.
- Dark mode via a `data-bs-theme` attribute (Bootstrap's own theming attribute — not a separate `data-theme`) toggled by `gth_theme_toggle`, backed by plain vanilla JS (`static/js/theme-toggle.js`). No Alpine.js involved: adapted from green-tech-hub.com's own real, working implementation, which is vanilla JS too.
  - **Where the choice lives.** `localStorage["gth-theme-mode"]` always holds it, as an internal implementation detail (see [docs/architecture.md](architecture.md#public-api-vs-implementation-details)). Since v0.12 the server can hold it too: with the optional `theme_save_url` the toggle also POSTs `theme=light|dark` there, and the optional `theme_mode` hands the saved preference back (see [docs/contract.md](contract.md#static-asset-globals)). So a signed-in user's theme follows them across browsers and devices, and localStorage is the fallback for anonymous pages or services without a settings store. A settings form that saves `ui.theme` applies it without a reload by sending the `gth:theme` event in its response, `toast("Preferences saved", events={"gth:theme": mode})`; the toggle and the form should read and write the same stored value, so they never disagree.
  - **Before first paint.** An inline anti-FOUC script in `app.html`'s `<head>` applies `theme_mode` when the page has one, else the stored localStorage choice. `"system"` follows `prefers-color-scheme`, live, until the user clicks the toggle. A consumer that sets neither and never renders the toggle (`gth_navbar(..., show_theme_toggle=False)`, the default) keeps today's always-dark default.
- **Density and motion follow the viewer** (v0.12). With greentechhub-core's `ui.density` / `ui.motion` in the optional `user_settings` (greentechhub-fastapi's `settings_context` supplies it), `app.html` puts `data-gth-density="comfortable|compact"` and `data-gth-motion="system|reduce|full"` on `<html>`; unknown or absent values add nothing.
  - **`compact`** gives fields, selects and segmented buttons Bootstrap's `-sm` sizing, tightens form and card spacing, and uses `table-sm` cells. `gth_data_table`'s own density toggle still wins for that table.
  - **`reduce`** cuts every transition and animation to ~0 (Bootstrap fades, toasts, the sidebar rail) and makes back-to-top jump instead of scroll. **`system`** follows `prefers-reduced-motion`, as before. **`full`** keeps gth's own animations even when the OS asks for less motion; Bootstrap's built-in reduced-motion rules still follow the OS.
- Brand tokens (colors) sourced from green-tech-hub.com's real palette (`#1FBE1E` primary — see `theme/tokens.py`) and reused everywhere, rather than each service picking its own accent color. The logo is original artwork — an abstract green circuit/leaf mark — designed for `greentechhub-ui`'s own brand identity, not a copy of GreenTechHub production's current logo (production still ships its own file at `addons/base/static/img/logo.png`; the two are intentionally decoupled for now, see `static/VENDORED.md`). Two files, for two different backgrounds: `static/logo/logo.png` is used for `logo_url` (the navbar on a dark background) and `static/logo/logo-light.png` — a stronger-outlined re-export of the same mark — for `logo_light_url` (the navbar in light mode) and, as `static/logo/favicon.png` — the mark on a dark (`#0b1f0b`) rounded-square tile, 64×64, made by `scripts/make_favicon.py`, so it fills the tab icon as a square on light and dark tab strips (the mark itself is portrait, so a tight crop still looked narrow) — for `favicon_url` (a browser's tab/chrome, whose background is unpredictable). `theme.brand_context(show_logo=True, static_url_prefix=...)` opts a consumer into all three (`None` by default, so adopting this doesn't change existing consumers' output).
- **The navbar follows the color mode** (v0.7): `gth_navbar` uses `bg-body-tertiary` and inherits `data-bs-theme`, rendering both logo variants and letting CSS show the one that suits its background; the brand text is `#A6EBA6` on dark and `#127a13` on light (both ≥4.5:1). Before v0.7 it was hardcoded `navbar-dark bg-dark` and stayed dark in light mode — pass `navbar_theme="dark"` (or the `navbar_theme` global / `shell_globals(navbar_theme="dark")`) to keep that look; it sets `data-bs-theme="dark"` on the `<nav>`, Bootstrap 5.3's replacement for `navbar-dark`.
- Color-mode-dependent theme values are custom properties set on every `[data-bs-theme]` element (`--gth-brand-fg`, `--gth-on-dark-display`, …) so a component inherits from its *nearest* themed ancestor — a dark-pinned navbar on a light page still gets its dark values. Prefer this over `[data-bs-theme=dark] .x` selectors, which match any ancestor.
- **Secondary buttons** (v0.7): Bootstrap's dark mode reuses its light greys, so `.btn-outline-secondary` text was `#6c757d` on `#212529` (3.3:1). `theme.css` retunes `.btn-secondary`/`.btn-outline-secondary` in dark mode (outline text `#ced4da`, 10.3:1; hover/active fills `#495057`/`#6c757d` with white or `#f8f9fa` text, ≥4.5:1) and keeps Bootstrap's own values in light mode. Checked `btn-check` controls (`gth_segmented`) pick up the active values. Replace either file + update its row in `static/VENDORED.md` whenever the artwork changes.
- Because `theme/` has no dependency on `components/` (see [docs/architecture.md](architecture.md#package-layout)), a service that only wants brand-consistent colors/typography without the full component library is already structurally possible. Not split into a standalone package today — kept as one repo until a real consumer (most likely GreenTechHub's Django app) needs branding without the component library.

## Static asset hosting

- **Bundled per service (recommended to start)**: each FastAPI service mounts `greentechhub_ui.static` at `/static`; Django does the equivalent via `STATICFILES_DIRS`. Simple, no extra infra.
- **Shared static host** (`static.green-tech-hub.com`, fronted by a reverse proxy): one copy, browser-cacheable across services. Worth it once there are enough services that duplication/versioning drift becomes a real annoyance — not needed for the first two consumers.

Either way, consumers never reference individual vendored files (`htmx.min.js`, `bootstrap.min.css`) by name — `app.html` resolves them internally, which is what keeps the "swap without breaking consumers" property true regardless of hosting choice. Concretely, `app.html` resolves every asset URL via a `*_url` global (see [docs/contract.md](contract.md#static-asset-globals)), so moving to a shared static host is a globals change, not a template change.
